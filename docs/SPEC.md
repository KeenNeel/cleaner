# cleaner 仕様書 (v0.2)

Windows PC のディスクを定期的・自動的に整理するツール。
「容量を空ける」「散らかったファイルを片付ける」「判断材料を出す」の 3 つを、**誤削除しない**ことを最優先に行う。

---

## 1. 前提・スコープ

| 項目 | 内容 |
|---|---|
| 対象 OS | Windows 10 / 11 (64bit) |
| 対象ドライブ | 内蔵ドライブ (C:, D: …) と **外付け HDD/SSD** すべて。ネットワークドライブ・光学ドライブ・USB メモリ (容量 64GB 未満のリムーバブル) は対象外 |
| 実行権限 | 通常ユーザー権限 (管理者権限は不要。システム領域は触らない) |
| 実装 | Python 3.12 + PySide6 (設定画面・タスクトレイ)、PyInstaller で exe 化 |
| UI | タスクトレイ常駐アイコン + 設定画面 + HTML レポート。CLI も併設 |
| 起動方法 | Windows タスクスケジューラによる定期実行 + トレイ/CLI からの手動実行 |
| 設定 | `%APPDATA%\cleaner\config.toml` (設定画面から編集。直接編集も可) |

### やらないこと (非スコープ)
- `C:\Windows`、`Program Files`、レジストリ、ドライバ等のシステム領域の掃除
- アプリのアンインストール
- デフラグ・SSD 最適化 (Windows 標準機能に任せる)
- クラウドストレージ (OneDrive 等) の「クラウドのみ」ファイルの中身読み取り

---

## 2. 機能一覧

| # | 機能 | 概要 | 既定の動作 |
|---|---|---|---|
| F1 | 不要ファイル削除 | 一時ファイル・キャッシュ・ゴミ箱・古いログ等 | 自動で隔離 |
| F2 | 重複ファイル検出 | 同一内容のファイルを全フォルダから検出 | 同一ドライブ内の重複は自動隔離、ドライブをまたぐ重複はレポート |
| F3 | ファイル仕分け | ダウンロード・デスクトップを種類/年月で `ドキュメント\Sorted` に振り分け | 自動で移動 |
| F4 | 古い/大きいファイル報告 | 長期間未使用・巨大ファイルの一覧 | レポートのみ |
| F5 | AI 不要判定 | 古い iPhone バックアップ等、ルールで決めにくいものを AI が判定 | 高確信度のみ隔離、他は承認待ち |

共通基盤: スキャナ / 隔離 (Quarantine) / 復元 / レポート / スケジューラ / ログ / ドライブ管理 / GUI

## 3. 安全設計 (全機能共通)

### 3.1 削除フロー
```
検出 → [隔離フォルダへ移動] → 保持期間 (既定 30 日) 経過 → 本削除
                     └── 期間中はいつでも元の場所に戻せる (GUI の「隔離ボックス」or `cleaner restore`)
```
- **即時削除はしない**。例外は「ゴミ箱を空にする」「ブラウザ等のキャッシュ」のように、元々使い捨てで復元価値がないものに限り、設定で `immediate = true` を許可する。
- 隔離フォルダは **各ドライブ直下** `X:\.cleaner_quarantine\` に置く (同一ボリューム内の移動なら瞬時・追加容量不要。ドライブをまたぐ移動は一切しない)。
- 隔離時に `manifest.jsonl` へ「元パス・ボリュームID・サイズ・更新日時・ハッシュ・理由・判定元(ルール/AI)・隔離日時」を記録する。manifest は **そのドライブの隔離フォルダ内** と `%LOCALAPPDATA%\cleaner\` の両方に保存する (外付けを別 PC に繋いでも復元情報が残る)。
- 注意: 隔離中は容量が空かない。ドライブごとに空き容量が閾値 (既定 10%) を切った場合は、隔離日の古いものから前倒し削除する (ただし最低保持 7 日は守る)。

### 3.2 絶対に触らないもの (ハード保護リスト)
- `C:\Windows`、`C:\Program Files*`、`C:\ProgramData`、`%APPDATA%` / `%LOCALAPPDATA%` (F1 の明示キャッシュ指定と F5 検出器の対象パスを除く)
- 実行中プロセスが開いているファイル (ロック中はスキップ)
- システム属性・隠しシステムファイル、シンボリックリンク/ジャンクションの先 (リンクは辿らない)
- Git リポジトリ内 (`.git` を含むディレクトリ配下)、仮想マシンディスク、データベースファイル
- ゲームライブラリ (Steam `steamapps`、Epic、Xbox `WindowsApps` 等)
- バックアップソフトの保存先 (ファイル履歴 `FileHistory`、`WindowsImageBackup`、Macrium/Acronis 等のイメージファイル)
- ユーザー設定 `protect` に列挙されたパス
- 更新日時が直近 24 時間以内のファイル (作業中の可能性)

### 3.3 初回実行
- 初回は必ず **ドライラン** (何も動かさずレポートのみ)。ユーザーが内容を確認し、設定画面またはトレイで「自動整理を有効にする」(`cleaner enable`) を押すまで、隔離・移動は行わない。
- 新しいドライブ (外付け含む) が初めて検出されたときも、そのドライブについては初回ドライランから始める。

---

## 4. ドライブ管理

- ドライブは **ボリュームシリアル/GUID で識別** する (ドライブ文字は外付けの差し替えで変わるため)。
- 設定画面の「ドライブ」タブで、ドライブごとに「対象にする/しない」「適用する機能 (F1〜F5)」を選べる。既定はすべて対象・全機能。
- 外付けドライブ:
  - 定期実行時に接続されていれば処理する。接続されていなければスキップ (エラーにしない)。
  - 接続中に実行していたら、作業を安全な区切りで止めてから取り外せるよう、トレイに「処理中」表示を出す。
  - 期限切れ隔離の本削除は、そのドライブが次に接続されたときに行う。
  - 外付けドライブを USB で接続した時点で自動実行する機能は **持たない** (意図しないタイミングで動かさない)。

## 5. 機能詳細

### F1. 不要ファイル削除
対象カテゴリ (それぞれ設定で ON/OFF・日数変更可):

| カテゴリ | 場所の例 | 条件 |
|---|---|---|
| ユーザー一時ファイル | `%TEMP%` | 7 日以上未更新 |
| ゴミ箱 | 各ドライブの `$Recycle.Bin` | 30 日以上前に捨てたもの |
| ブラウザキャッシュ | Chrome / Edge / Firefox の Cache ディレクトリ | ブラウザ未起動時のみ |
| サムネイルキャッシュ | `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*` | 常に |
| クラッシュダンプ | `%LOCALAPPDATA%\CrashDumps` | 30 日以上 |
| 中断ダウンロード | `*.crdownload` `*.part` `*.tmp` (Downloads 内) | 7 日以上 |
| 開発系キャッシュ | `node_modules`, `__pycache__`, `.gradle` 等 | **既定 OFF**。有効時も 90 日以上未更新のプロジェクトのみ |

### F2. 重複ファイル検出
- 対象: **全ドライブの全フォルダ** (3.2 の保護対象を除く)。
- 手順: サイズで絞る → 先頭/末尾 64KB のハッシュ → 全体ハッシュ (BLAKE2b。外部ライブラリを増やさないため標準ライブラリのものを使う) で確定。ハッシュは `%LOCALAPPDATA%\cleaner\hashcache.db` にキャッシュし、サイズ・更新日時が変わっていないファイルは再計算しない。
- 対象外: 1KB 未満、ハードリンク同士、保護パス内、アプリのインストールフォルダ内 (exe/dll と同居するファイル)。
- **残す 1 つの選び方** (優先順): ① 設定 `keep_priority` に指定したフォルダ内 (既定: `ドキュメント` > `ピクチャ` > `ビデオ` > `ミュージック` > その他 > `デスクトップ` > `ダウンロード`) → ② パスが浅い → ③ 作成日時が古い。
- 自動隔離の範囲:
  - **同一ドライブ内の重複**: 残す 1 つ以外を自動で隔離する。
  - **ドライブをまたぐ重複** (例: C: と外付け HDD に同じ写真): 意図的なバックアップの可能性が高いので **自動隔離しない**。レポートに一覧表示し、ユーザーが承認したもののみ隔離。
  - フォルダ丸ごとの重複 (中身が 100% 一致するフォルダ) はフォルダ単位でまとめてレポートし、承認制とする (フォルダ構造ごと残したいケースが多いため)。

### F3. ファイル仕分け
- 対象フォルダ: 既定 `ダウンロード`, `デスクトップ` (直下のファイルのみ。サブフォルダは触らない)。
- 条件: 最終更新から 3 日以上経過、ロックされていない、中断ダウンロードでない、ショートカット (.lnk/.url) でない。
- 移動先はすべて **`ドキュメント\Sorted\`** 配下 (既定、設定で変更可):

| 種類 | 拡張子例 | 移動先 |
|---|---|---|
| 画像 | jpg, png, heic, gif, webp | `ドキュメント\Sorted\画像\{YYYY-MM}` |
| 動画 | mp4, mov, mkv | `ドキュメント\Sorted\動画\{YYYY-MM}` |
| 音声 | mp3, m4a, wav, flac | `ドキュメント\Sorted\音声\{YYYY-MM}` |
| 文書 | pdf, docx, xlsx, pptx, txt | `ドキュメント\Sorted\文書\{YYYY-MM}` |
| 圧縮 | zip, 7z, rar | `ドキュメント\Sorted\圧縮\{YYYY-MM}` |
| インストーラ | exe, msi | `ドキュメント\Sorted\インストーラ` (90 日後に F1 対象として隔離) |
| その他 | — | 移動しない |

- `{YYYY-MM}` はファイルの更新日時 (写真は EXIF 撮影日があれば優先)。
- 同名ファイルがある場合は ` (1)` 等の連番を付与。移動履歴も manifest に記録し、元に戻せる。
- 注意: `ドキュメント` が OneDrive と同期されている場合、仕分けたファイルはクラウドにアップロードされる。初回起動時に検出して警告し、移動先を変えるか確認する。
- 仕分け元と移動先が別ドライブになる場合 (例: D: のダウンロード → C: のドキュメント) はコピー→検証→元を削除の順で行い、途中で失敗したら元を残す。

### F4. 古い/大きいファイル報告
- 「大きい」: 既定 1GB 以上。「古い」: 最終アクセス 1 年以上 (NTFS の最終アクセス更新が無効な環境では最終更新日時で代替)。
- ドライブ別・フォルダ別の容量ランキング (上位 20) も出す。
- **自動で動かさない**。GUI の「承認待ち」画面から選んで隔離できる。

### F5. AI 不要判定
ルールだけでは決めにくいが「たぶん要らない」ものを、AI (Claude API) に判定させる。

**検出器 (ルールで候補を拾う → AI が判断する) の初期セット:**

| 検出器 | 内容 | 判定ルール |
|---|---|---|
| iPhone/iPad バックアップ | `%APPDATA%\Apple Computer\MobileSync\Backup\*` と `%USERPROFILE%\Apple\MobileSync\Backup\*` (+ 他ドライブに移したバックアップ) | `Info.plist` からデバイス名・機種・シリアル・最終バックアップ日を取得。**端末ごとに最新 1 件だけ残し、それより古いバックアップは不要** と確定 (AI 不要のルール判定)。AI には「1 年以上バックアップのない端末 (機種変更済みの旧端末など) の最新バックアップ」を判定させ、これは承認制とする |
| 古いインストーラ | 既にインストール済みアプリのインストーラ | インストール済み一覧 (レジストリ読み取りのみ) と照合 |
| 古いドライバ/SDK 展開物 | `C:\NVIDIA`, `C:\AMD`, 展開済み SDK 等 | 作成日・サイズ |
| 放置プロジェクト/ビルド成果物 | `bin/obj/dist/build` 等 | 最終更新日 |
| 旧 Windows 更新残骸の案内 | `C:\Windows.old` | 管理者権限が要るので**案内のみ** (「ディスク クリーンアップ」を促す) |

**AI に渡すもの / 渡さないもの:**
- 渡す: パス、サイズ、作成/更新/アクセス日時、拡張子、検出器が抽出したメタ情報 (例: バックアップのデバイス名・機種・日付)。
- **渡さない: ファイルの中身**。ユーザー名部分のパスはマスク (`C:\Users\<user>\...`)。
- AI 機能は API キーを設定画面で登録した時点で有効化できる (既定 OFF、明示的に ON にする)。

**API キーの扱い:**
- Windows 資格情報マネージャー (Credential Manager) に保存する。`config.toml` やログには書かない。
- 設定画面に「接続テスト」ボタンを置く。
- 月間の API 利用上限 (既定 500 円相当のトークン数) を設定でき、超えたらその月は AI 判定をスキップしてレポートに記載。

**AI の出力と扱い:**
- 出力: `{判定: 不要/要確認/必要, 確信度: 0-1, 理由: 文章}`
- 自動隔離: 判定「不要」かつ確信度 ≥ 0.9 かつ検出器ごとの `auto_quarantine = true` のときのみ。
- それ以外は GUI の「承認待ち」に理由付きで表示。
- AI は削除を直接実行しない (常に隔離フロー経由)。

## 6. GUI

### 6.1 タスクトレイアイコン
- Windows ログイン時に自動起動して常駐 (設定で OFF 可)。常駐しなくても定期実行はタスクスケジューラで動く。
- アイコンの状態: 通常 / 実行中 (アニメーション) / 承認待ちあり (バッジ) / エラーあり。
- ホバー: 「前回: 10/5 03:12 (12.3GB 空き) / 次回: 10/12 03:00 / 承認待ち 4 件」
- 右クリックメニュー:
  - 今すぐ整理する / ドライランする
  - 実行の一時停止・再開・中止
  - 承認待ちを確認… (件数表示)
  - 隔離ボックスを開く…
  - 最新レポートを開く
  - 設定…
  - 自動整理: 有効/無効 (チェック)
  - 終了
- 完了時にトースト通知 (「12.3GB 空きました / 承認待ち 4 件」)。クリックでレポートを開く。

### 6.2 設定画面 (タブ構成)

| タブ | 主な項目 |
|---|---|
| 全般 | 自動整理の有効/無効、隔離保持日数、空き容量閾値、ログイン時に常駐、通知 ON/OFF |
| スケジュール | 頻度 (毎日/毎週/毎月)、曜日・時刻、AC 電源時のみ、アイドル時のみ、実行時間上限 |
| ドライブ | 検出済みドライブ一覧 (名前・容量・空き・接続状態)、ドライブごとの対象 ON/OFF と適用機能 |
| 不要ファイル (F1) | カテゴリごとの ON/OFF と日数 |
| 重複 (F2) | 残す優先順位 (ドラッグで並べ替え)、ドライブまたぎの扱い、最小サイズ |
| 仕分け (F3) | 対象フォルダ、移動先ルート、種類ごとのルール編集 (拡張子・移動先)、経過日数 |
| レポート (F4) | 大きいファイルの基準、古いファイルの基準 |
| AI (F5) | 有効/無効、API キー登録・接続テスト、モデル、確信度しきい値、月間上限、検出器ごとの ON/OFF と自動隔離 |
| 保護フォルダ | 保護パスの追加・削除 (フォルダ選択ダイアログ)、ハード保護リストの表示 (編集不可) |

- 「保存」で `config.toml` を書き換え、スケジュール変更はタスクスケジューラに即反映。
- 入力値は保存前に検証 (存在しないパス、0 日以下など)。

### 6.3 承認待ち画面
- F2 (ドライブまたぎ・フォルダ重複)、F4、F5 の承認制項目を一覧表示。
- 列: 種類、パス、サイズ、理由 (AI 判定ならその文章と確信度)、検出日。
- 操作: 選択して「隔離する」/「今後も無視する」/「エクスプローラーで開く」。

### 6.4 隔離ボックス画面
- 隔離中・仕分け済み項目の一覧 (ドライブ、元パス、サイズ、理由、隔離日、本削除予定日)。
- 操作: 「元に戻す」(選択/日付指定/すべて)、「今すぐ本削除」、検索・絞り込み。
- 外付けで未接続のドライブの項目はグレー表示 (操作不可)。

## 7. 定期実行

| 項目 | 既定 |
|---|---|
| 頻度 | 毎週日曜 3:00 (タスクスケジューラ) |
| 条件 | AC 電源接続時、PC アイドル 10 分以上 |
| 見逃し時 | 次回起動後に実行 |
| 処理順 | 期限切れ隔離の本削除 → F1 → F3 → F2 → F5 → F4 → レポート生成 |
| 実行時間上限 | 2 時間 (超えたら中断し次回継続。重複検出は途中結果をキャッシュして再開) |
| 負荷 | 低優先度プロセス・I/O 優先度低で動作。ユーザーが操作を再開したら一時停止 |
| 通知 | 完了時にトースト通知 |
| 多重起動防止 | 実行中に手動実行が来たら、実行中の処理の進捗を表示するだけ |

## 8. CLI
GUI と同じ処理をコマンドでも実行できる (スクリプト・トラブル調査用)。

```
cleaner scan                 # ドライラン (何も変更せずレポート生成)
cleaner run [--dry-run] [--drive D:]   # 整理を実行
cleaner report               # 最新レポートをブラウザで開く
cleaner approve <id...>      # 承認待ち項目を隔離
cleaner restore <id|--all|--since DATE>   # 隔離/移動を元に戻す
cleaner purge [--older-than 30d]          # 隔離フォルダの本削除
cleaner enable / disable     # 自動実行の有効化/無効化
cleaner schedule install|uninstall
cleaner gui                  # トレイアイコンを起動
```

---

## 9. レポート
- HTML 1 ファイル (`%LOCALAPPDATA%\cleaner\reports\YYYY-MM-DD.html`)。過去 12 回分を保持。
- 内容: 空いた容量 (ドライブ別・カテゴリ別)、隔離した項目、仕分けした項目、重複一覧、古い/大きいファイル、AI 承認待ち (理由付き)、未接続でスキップしたドライブ、エラー/スキップ一覧。
- 操作 (承認・復元) は GUI で行い、レポートは閲覧用とする。

## 10. 設定ファイル例 (`config.toml`)

```toml
enabled = false            # 初回はドライランのみ
quarantine_days = 30
min_free_percent = 10
start_with_windows = true

protect = ['D:\Work', 'C:\Users\me\Important']

[schedule]
frequency = "weekly"       # daily / weekly / monthly
day = "sun"
time = "03:00"
ac_only = true
idle_minutes = 10
max_hours = 2

[drives]
# ボリュームGUID で識別。未記載のドライブは既定 (全機能 ON、初回ドライラン)
"{1a2b...}" = { label = "外付けHDD", enabled = true, features = ["F1", "F2", "F4"] }

[cleanup]
temp_days = 7
recycle_bin_days = 30
browser_cache = true
dev_caches = false

[dedupe]
min_size_kb = 1            # CLI の --min-size 100MB で一時的に変更可
cross_drive = "report"     # report / quarantine
keep_priority = ['~\Documents', '~\Pictures', '~\Videos', '~\Music', '*', '~\Desktop', '~\Downloads']

[organize]
dirs = ['~\Downloads', '~\Desktop']
dest_root = '~\Documents\Sorted'
min_age_days = 3

[report]
large_file_gb = 1
old_file_days = 365

[ai]
enabled = false
model = "claude-opus-5-5"   # コスト重視なら claude-haiku-5-5
auto_quarantine_threshold = 0.9
monthly_budget_jpy = 500
# API キーは Windows 資格情報マネージャーに保存 (ここには書かない)

[ai.detectors]
iphone_backup = { enabled = true, auto_quarantine = true, keep_latest_per_device = 1 }
old_installers = { enabled = true, auto_quarantine = false }
```

## 11. ログ・エラー処理
- ログ: `%LOCALAPPDATA%\cleaner\logs\` (日次ローテーション、90 日保持)。API キーやファイル内容は記録しない。
- アクセス拒否・ロック中・パス長超過 (260 文字超は `\\?\` 形式で対応) はスキップしてレポートに記載。処理全体は止めない。
- 隔離移動中にエラーが起きた場合は manifest に書く前に元に戻す (中途半端な状態を残さない)。
- 処理中に外付けドライブが取り外された場合は、そのドライブの処理を中断し、manifest との整合性を次回接続時に検査・修復する。
